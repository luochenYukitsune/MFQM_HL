# MFQM Minecraft 1.21.11 / NeoForge — 实现路线图

> 2026-10-06 更新：内容实现已取代此前空框架。保留原 9 阶段、41 个任务编号作为索引，按实际代码重写状态；未运行的体验验收不标为通过。当前证据见[玩法移植报告](../2026-10-06-gameplay-port/final_report.md)和[审查记录](../2026-10-06-gameplay-port/review.md)。

基于 MoreFunQuicksandMod 1.1.1 / 1.7.10 编译产物和资产的移植，包根为 `com.mfqm.morefunquicksandmod`。版本由构建和元数据定义，工作目录名称不定义兼容性。旧版库存见[移植前对照](../2026-10-05-legacy-content-audit/comparison.md)。

## Phase 1: 基础与版本

### Task 1.1: 项目保留与旧版取证

保留原工作区修改。旧目录为编译产物和资源；已恢复 158 个反编译 Java，并恢复巨大生成方法。完整库存见旧版对照文档。

### Task 1.2: 构建目标

Minecraft 1.21.11 / NeoForge 21.11.45 / Java 21，Gradle 9.2.1、ModDevGradle 2.0.148。开发运行目录按版本隔离。

### Task 1.3: 入口

MFQM 注册方块、物品、流体、实体、方块实体、网络、附件、配方条件及世界生成。客户端事件按 Dist.CLIENT 隔离。

### Task 1.4: 配置

81 个配置值：66 SERVER、6 CLIENT、9 COMMON。恢复缺失世界生成、手救援、slime 总开关和兼容设置。旧 82 项移除 3 个数字 DataWatcher 槽位，改为附件；另保留 2 个独立客户端效果开关。

### Task 1.5: 注册与标签

49 方块、13 流体对、178 物品、16 实体、4 方块实体。标签已填入成员；状态和注册不会随获取配方的配置开关消失。

### Task 1.6: 元数据

声明精确 Minecraft [1.21.11]、NeoForge [21.11.45,)，保留版权和作者署名。包含 logo、默认 AT；使用 NeoForge 提供的包元数据。

### Task 1.7: 语言与内容库存

英文和俄文各保留 242 个原始语言键，添加现代 ID、控制键和死亡消息。43 个旧独立物品注册调用按 metadata 拆为 46 个现代独立物品。

### Task 1.8: 数据生成

5 个伤害类型及伤害、方块、流体、生物群系标签共 19 JSON。手工转换的模型/配方/结构数据为版本控制输入，不由空模型提供器覆盖。

### Task 1.9: 静态资源

246 张原始 PNG 像素保留，48 个动画文件。mucus_flowing 显式使用 32×16 帧；2 个原始蜜蜂 OGG 和标志保留。

### Task 1.10: 基础验收

编译、数据生成、服务器世界加载和客户端资源加载均已运行。最终 JAR 证据集中记录于本次 final_report.md。

## Phase 2: 流体

### Task 2.1: 类型

ModFluids 注册 13 对源/流动实例与 FluidType。不能因旧 Fluid 关联把普通固体沉陷方块全部变为现代液体。

### Task 2.2: 方块与模型

13 LiquidBlock 按 LEVEL 状态工作，其余方块保留 VARIANT。源/流动实例均进入流体标签，模型和动画经过客户端烘焙。

### Task 2.3: 接触和呼吸

QuicksandPhysics 在服务端合并身体/眼部接触，同 tick 仅处理一次。两种 Liquid Mire 使用原版空气；其他符合呼吸条件的介质使用附件空气，避免双扣和双伤害。悬垂苔藓按实际跨格形状检测。

### Task 2.4: 容器

保留旧桶映射、两种粘土、共用 Mire 桶、原版沙子的粉末桶和巧克力粉普通物品。测试源块收集、流动块拒绝、状态放置和空桶返回。

### Task 2.5: 客户端扩展

LegacyFluidRendering 注册静态/流动贴图、透明层、fog 和水下表现；13 种流体资源已实际加载。视觉完全一致仍需人工体验对照。

## Phase 3: 固体与机关

### Task 3.1: 沉陷模型

采用 LegacyMediumBlock / SinkingMaterial / SinkingMotion / QuicksandPhysics 分离状态碰撞、材料参数和共享物理。普通 peat、软蜡和上下花板保留独立碰撞。

### Task 3.2: 全部方块

49 个旧身份、36 个固体 VARIANT 家族。MediumReactions 处理热/湿度/软化/气体/融合/生长/肉壁；支持 4 种机关方块实体。修复仅 Sinky 液体可融合地形及下界废物出口条件。

## Phase 4: 物品

### Task 4.1: 装备

气体面罩、救生衣、涉水靴及两种前置靴采用现代 Equippable；浮力、负重、污染和防护由实际装备读取。救生衣潜行关闭浮力。

### Task 4.2: 工具

长棍、绳、抓钩、手救援、液体枪、肥料及相关材料已实现。网络只提交输入和连接控制意图。

### Task 4.3: 投射

药水和液体弹区分弱流量；药水中心 LEVEL=4、周边=7，液体枪=7。普通弹药不能产生可收桶的源液体或融合地形。

### Task 4.4: 食物

恢复幼虫、蔓越莓、甜甜圈及三种饮品的食物/效果/返回瓶规则；饮用沉陷药水支持仙人掌生长黏液花。

### Task 4.5: 其他物品

蜡、peat 燃料、蜂巢物品、线缆/卷轴/过滤器等材料。rescuing 作为临时手持物品隐藏并在连接结束时清理。

### Task 4.6: 配方与获取开关

205 个核心配方覆盖 85 个旧注册调用，128 个地毯颜色配方包含在内。9 条外部配方由标签映射兼容桥处理。SERVER 获取开关在冷启动配置加载后过滤，/reload 按条件加载；禁用 longStick 已实测。

## Phase 5: 生物与辅助实体

### Task 5.1: AI

4 种 blob 共享适当基础但保留不同参数、捕获/吞陷、逃脱、分裂、盗取/归还物品等行为；蜜蜂围绕蜂巢活动。

### Task 5.2: 角色

16 种实体角色与 5 个刷怪蛋，不把 16 个辅助角色全部当普通怪物。触手仅允许泥、丛林流沙、软流沙与吞噬肉对应坑。

### Task 5.3: 生成

自然生成谓词和生物群系 modifier 接入配置；blob 总开关及分项开关按运行状态判断。生态密度尚未证明与旧版相同。

## Phase 6: 客户端

### Task 6.1: 模型

LegacyBlobModel、LegacyBeeModel 和 LegacyCoatingModel 保留旧纹理，现代姿态和状态适配。

### Task 6.2: 渲染

blob、蜜蜂、辅助实体和投射物各有 renderer；动态机关使用 MechanismRenderer。16 种创建和 renderer 注册已验证，辅助几何不声称逐像素相同。

### Task 6.3: HUD与覆盖

空气 HUD、污染图层、第一人称手臂、被覆盖视野和强制第一人称接入客户端配置。呼吸 HUD 包含原版 Mire 空气。

### Task 6.4: 效果

气泡、tar 脚印等辅助效果独立于服务端伤害；粒子 JSON/provider 和纹理资源有实际绑定。

## Phase 7: 世界生成

### Task 7.1: 地貌与结构

LegacyTerrainFeature / LegacyStructures 实现介质坑、蜡树、蜂巢、蛛巢、花和下界肉/酸/废物地貌；位置受构建高度和可写范围限制。一次选择一类地貌，避免所有介质叠加。

### Task 7.2: 旧草案 carver

旧路线图中的独立 MudCarver / MireCarver 没有对应旧版注册证据，已由实际坑/洞地貌 Feature 取代；不额外虚构两个内容。

### Task 7.3: 沙漠墓

恢复旧固定生成代码为 48×20×27 NBT 模板，8504 个放置操作，9 箱/6 刷怪笼；奖励数据、随机骷髅/僵尸和神殿 TNT 机关转换已接入。

### Task 7.4: 配置与兼容

Biome modifiers、placed features、structure/set 已发布为数据。COMMON 兼容标志及命名空间/标签决定选入；不沿用数字维度或反射替换。外部实际合载需具体依赖和映射。

## Phase 8: 状态与网络

### Task 8.1: 附件

SinkingState 使用 Value I/O 和 STREAM_CODEC；污染持久化，临时接触/输入字段独立，死亡不复制附件。修改后通过现代附件同步。

### Task 8.2: 意图消息

主线程处理绑定连接的所有者、工具、同维度、距离及重复 tick 限制。客户端不能直接声明救援成功、伤害或任意速度。

### Task 8.3: 救援生命周期

已测试实际玩家乘客捕获/释放、手救援开始与使用动画、连接释放、双方死亡及救援者维度变化后的清理。双真人网络和断线/完整复活流程尚未实测。

## Phase 9: 验收与发布产物

### Task 9.1: 资源完整性

静态校验检查 178 个注册物品对应的定义、方块模型引用、205 核心配方、装备纹理、动画尺寸、墓/奖励资源；可额外与旧目录逐字节比较 PNG 和语言键。

### Task 9.2: 平衡

14 项运动断言与服务端介质行为检查通过；旧版体验中的系数、AI、地貌密度、基础箱奖励池存在现代适配差异，未宣称完整数值一致。

### Task 9.3: 集成验收

独立服务器检查涵盖桶、食物、弹药、呼吸、苔藓、捕获、手救援、废物出口、箱奖励与配方。客户端验证 178/162/49/13/16。跨模组合载与双真人长时体验列为验证边界。

### Task 9.4: 构建结果

最终构建和成品元数据/Java 65/资源校验以本次 final_report.md 的实际输出为准。当前请求授权本地实现和验收，未创建 PR、提交或发布。

## API依据

开发核对了 NeoForge 21.11.45 的精确目标源码，并参考官方 [1.21.11 迁移说明](https://docs.neoforged.net/primer/docs/1.21.11/)、[生物群系 modifier](https://docs.neoforged.net/docs/1.21.11/worldgen/biomemodifier/)和[访问转换器](https://docs.neoforged.net/docs/1.21.11/advanced/accesstransformers/)。普通构建依赖版本控制的源码和资源，不依赖本地反编译缓存。
