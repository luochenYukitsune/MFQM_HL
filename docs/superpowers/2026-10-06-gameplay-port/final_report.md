# MFQM 1.21.11 移植与验收结果

日期：2026-10-06。目标：**Minecraft 1.21.11 / NeoForge 21.11.45 / Java 21**。

本轮将原来的空框架补为可运行的玩法模组。按 MoreFunQuicksandMod 1.1.1 / 1.7.10 编译产物、反编译代码和资产恢复内容身份、状态及核心交互，重写目标版本的物理、实体、客户端和生成 API。

## 已实现库存

- 49 个原始方块身份，36 个固体 VARIANT 家族，13 对源/流动流体及 FluidType。
- 178 个注册物品：49 个基础方块物品、78 个状态变体、46 个现代独立物品和 5 个刷怪蛋。创造栏实际显示 **162 项**；机关/临时工具和不可独立获得的状态隐藏。
- 16 种实体角色、4 种方块实体。已接入捕获/吞陷、不同 blob 参数、盗取/归还、触手、蜜蜂、绳/抓钩/手救援及液体投射。
- 205 个核心配方覆盖旧版 85 个调用；9 条语义映射模板覆盖其余 9 调用，共覆盖 94 个原调用。128 条彩色地毯配方包含在 205 内。
- 5 件可穿戴装备、桶、液体枪、肥料、食物、饮品、燃料、长棍与救援工具；空气、污染、挣扎、负重和恢复由服务端处理。
- 主世界/下界介质地貌、蜂巢、蜡树、蛛巢、花、废物出口、神殿转换及沙漠墓。墓模板由旧固定放置代码转换，48×20×27，8504 个放置操作、9 箱、6 刷怪笼；197 操作的黏液花可生长/重长。
- 81 个配置：66 SERVER、6 CLIENT、9 COMMON。原 82 项去除 3 个数字 DataWatcher 槽位并用附件替代，另保留 2 个独立客户端效果开关。获取工具的配置控制配方，注册身份稳定。

当前客户端物品定义目录包含 640 个 JSON，其中有未注册的状态候选；178 是实际注册身份数，不能将目录总文件数当作物品数。

## 资源和兼容

原 246 张 PNG 已在成品中逐字节核对，没有重绘原像素；英文/俄文各 242 个旧键和值保留。48 个动画文件恢复，32×304 的流动黏液条带显式采用 32×16 帧。保留 2 个蜜蜂 OGG、标志及 5 张装备贴图的现代路径副本。

模型、配方、装备、奖励、特征和结构为版本控制资源；5 个伤害类型和标签由数据生成输出为 19 个 JSON。普通构建不需要旧目录或反编译缓存。

可选配方默认使用空语义标签。依赖物品映射完整后才创建真实 RecipeHolder；外部输出必须只有一个明确物品，不猜测旧数字 ID 或 metadata。标签或模板改变时在同步前重新构建配方显示和熔炉属性，普通同 ID 数据包配方优先。映射说明见 [compat-recipes.md](compat-recipes.md)。

## 验证边界和适配差异

内容身份和核心流程已经恢复；现有证据不能证明与 1.7.10 逐数值、逐像素或相同种子的世界完全一致。运动系数、现代 AI、地貌密度、部分辅助几何使用目标版本适配；箱奖励保留旧 MFQM 增加项，但原版基础类别池和注册物品奖励采用现代注册表语义。

真实第三方合载、双真人网络及完整断线/复活/长时体验尚未验收。旧外部 metadata 物品须由数据包明确映射；模板 fixture 验证不等于第三方合载通过。旧反射删除第三方配方改为整合包明确覆盖实际冲突 ID。当前任务完成本地实现、修复、打包和上述验收，未创建 PR、提交、合并或对外发布。
