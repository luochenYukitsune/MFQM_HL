# MFQM 1.21.11 玩法移植审查

日期：2026-10-06。目标：Minecraft 1.21.11 / NeoForge 21.11.45 / Java 21。

## 范围和依据

依据旧 1.1.1 的注册字节码、158 个反编译 Java、恢复后的巨大生成方法及原始资源，对照现代注册、碰撞/物理、物品、实体、世界生成、客户端和网络。实现阶段使用独立子代理分工，最终由主代理统一编译、运行和修复，独立只读审查复核代码。

目标 API 核对精确依赖源码。线上参考采用官方 [1.21.11 迁移说明](https://docs.neoforged.net/primer/docs/1.21.11/)、[Biome modifiers](https://docs.neoforged.net/docs/1.21.11/worldgen/biomemodifier/)和[Access transformers](https://docs.neoforged.net/docs/1.21.11/advanced/accesstransformers/)。旧箱奖励类别参考 [Forge 1.7.10 ChestGenHooks 原始源码](https://raw.githubusercontent.com/MinecraftForge/MinecraftForge/1.7.10/src/main/java/net/minecraftforge/common/ChestGenHooks.java)。

## 已修复问题

1. **介质溺水缺失**：两种 Liquid Mire 原来禁止原版溺水且跳过自定义空气，普通生物无法溺水。现只由原版空气处理正常沉浸；其他介质按其呼吸策略处理，不双扣空气。真实 baseTick、空气耗尽及受伤验收通过。
2. **触手坑选择不一致**：产生后因无效坑立即消失。统一四种旧版允许介质的选择和有效性判定；实际生成、首 tick 存活、成长及拉力检查通过。
3. **苔藓悬垂形状遗漏**：身体/眼睛位于上方方块伸出的苔藓中时被当空气。按实际跨格上下界和连通段检测，模型同步修正；七种状态检查通过。
4. **救生衣潜行失效**：浮力未考虑潜行。潜行关闭浮力、释放后恢复；运动断言覆盖两种输入。
5. **普通液体弹改变地形和生成源**：限制融合到 Sinky 液体，恢复枪/药水弱流量。水、岩浆、蜂蜜弹不能收桶回填或融合周边地形，实际回调验收通过。
6. **废物出口无法触发**：生成缺少完整支撑柱，且随机回调又叠加固定时间相位。生成有效六格柱和支撑，保留随机排泄条件；下界实际生成出口、产出 slurry、破坏支撑后拒绝产出均通过。
7. **冷启动配置晚于配方解析**：SERVER 获取开关首次开服不能过滤配方。配置加载后重新过滤 RecipeMap 并 finalize；重载直接使用已加载配置。关闭长棍的注册存在性和实际合成、/reload 均通过。默认 AT 仅开放 RecipeManager.recipes。
8. **奖励使用占位内容**：恢复旧墓的 17 个奖励增加项、数量、权重和抽取范围，蜂巢保留旧奖励项和注册物品随机奖励语义；使用现代原版基础类别池替代移除的 ChestGenHooks。三张表实际解码及多随机种子出物通过。
9. **手救援握持动作缺失**：绑定成功时启动持物使用状态，使用临时物品维持连接，移除时停止使用并清理物品。释放、双方死亡及救援者维度变化均有运行断言。

其他修正包括蜂巢完整范围预检、蜡树先坑后树干、墓中刷怪笼按旧类型随机、区块转换只扫描含目标的 section、移除空模型提供器与无引用奖励表，以及低海拔生成的安全高度夹取。

## 可选配方复核

205 个核心配方覆盖 85 个旧调用，其余 9 调用均有可映射模板。默认空 tag 静默禁用，无旧数字 ID 或 metadata 猜测。输入支持等价候选，输出要求单个明确物品；组件负载和嵌套 AND 谓词不展开成额外材料。

数据包普通配方拥有同 ID，即使条件为 false，兼容桥也不能将它重新启用。注入 holder 通过对象身份追踪，重载时更新或移除自身配方，保留别人替换的同 ID holder。同步之前重新构建配方显示和熔炉属性。完整 fixture 实际经历冷启动 9 条、/reload 9 条、禁用映射后 0 条。

## 验证边界

运行断言能证明指定回调和资源路径，不能替代双真人网络、所有第三方真实合载、全部配置组合或长时体验。下陷系数、AI、生态密度、现代原版奖励池、部分辅助几何属于新版适配，未宣称与 1.7.10 每个数值/像素一致。旧 BOP 反射删除他人配方的做法改为整合包明确覆盖冲突配方。

最终构建和运行证据见 [final_report.md](final_report.md)。

## 最终复核闭环

独立复核未发现新的 P0/P1；9 个兼容模板的来源、形状、数量及 metadata 语义与旧代码一致，嵌套 ingredient、同 ID 保护和同步时序符合设计。

复核另发现并修复两项测试工具 P2：重复 server.properties 安全键可能覆盖测试世界/监听地址；设置或启动阶段抛错可能跳过恢复。现拒绝受保护键重复、转义/别名和续行等歧义，所有修改及进程启动纳入统一 try/finally，保持原配置字节并清理部分写入的临时包。四组隔离/故障回归通过，独立只读复核确认两项闭环。源码/文档数量和 41 个路线图编号也已复核。
