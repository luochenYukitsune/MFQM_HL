# 玩法和实际客户端增量终审

审查范围：胶水静止深度、原版跳跃、黏连与粘鼠板释放、跨维度清理、客户端输入及第一人称手部、实际安装 JAR 启动器。源码先独立只读审查，发现问题后由主任务批准转为定向修复，再由独立审查者复核新增代码。下列结论截至 2026-10-07 12:25:02 的实际游戏验证。

## 已关闭的 Major

- 胶水取消重力后，NeoForge 原版 fluid jump 仍会持续向上移动。实际客户端持续 space 60 tick 的 RED 浮升约 1.209 格。双侧窄范围调用条件抑制原版上升冲量，保留真实挣扎意图及救援速度。安装 JAR GREEN 的起始、服务器和最高客户端 Y 均为 252.75，服务器 effort 仍增长。
- 涂胶板只在 Post 清速度，原版地面跳跃会先离开薄板。实际客户端 RED 最高浮升约 1.486 格。相同 hook 增加当前真实板接触及释放 episode 的匹配，服务器和客户端同步释放标志、位置和上次涂胶量，协议升级至 3。安装 JAR GREEN 全新板的起始、服务器和最高客户端 Y 均为 253.0625。
- 旧 `newBoard` 判断将已挣脱角色的跳起/落回当成新捕获。独立审查发现后，真实猪回归在补胶前已失败。最小调整短暂离开的重置分支，保留真正新板/补胶/结束旧 episode 的重置。真实服务器验证完整落回后的第二次跳跃，以及之后补胶、新板重新困住、耗尽板恢复跳跃。

## 验收夹具修正

截图中的牛与玩家实际选中了同一块板，即使 NoAI 仍正常自救并消耗共享涂层。最终边界验收因此在个人 effort 30.25 时涂层合法耗尽，无法继续累积至 34。真实诊断日志确认涂层比个人磨耗提前少 1。仅在照片完成后将牛移到独立受支撑板，生产磨耗规则和 34 effort 门槛均保留。重新安装 JAR 验收达到真实 effort 34，并验证仍有涂胶板上的普通跳跃和落回 release 状态。

## 其余复核结论

- 跨维度事件与 fallback 在同 clock 去重之前清除旧世界 helpers、board drag、胶水 gravity modifier、原始输入和动画；目的维度同一 clock 可以重新建立接触。短距同维度 teleport 保留连接，与合法拉伸展示用途一致。
- 原始跳跃 intent 保留，取消的仅为受困目标的原版上升冲量。实际普通猪、客户端创造免疫、救援上升和干地跳跃有直接位移证据。已释放板的位置及涂层量必须匹配，耗尽板直接从真实方块状态放行。
- 第一人称手持物调用 vanilla `renderArmWithItem` 不再次派发 RenderHandEvent，没有事件递归。对应 AT 已在实际安装 JAR 客户端验证；客户端类入口限定客户端，真实专服启动没有客户端 class-loading 失败。
- 启动器在启动前以 TOML 解析 FML 配置，以无 BOM UTF-8 写入；隔离实例使用文件锁，错误路径仅结束自己启动的 Java PID。后续诊断还保留短时间的输出排空以保存堆栈。没有操作桌面导出或用户游戏存档。
- 最终胶水生成坡度/树冠增量只读复核未发现新增 Major：半径和封边在同一 chunk，最低天然地面与两格土岸头部清理一致，封边和底层保持天然实心，液体、方块实体、床岩、树干和人工方块拒绝；实际自然分布结果由主任务独立世界样本记录。
