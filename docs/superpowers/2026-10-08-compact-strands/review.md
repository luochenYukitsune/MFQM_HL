# 代码审查

审查基线 `c12c749`，范围为第一人称脚部对齐、短密束显示和追加的身体覆盖贴合调整。按用户节省开支的要求，由主代理逐项审查，没有新增子代理。

## 规格符合性

- 第一人称脚点取自当帧实际相机角色状态，包括上游临时位置与姿势。旧版实际游戏断言出现 0.25 格偏差，修复后的真实身体腿矩阵与黏丝端点偏差小于 0.000001 格。
- 每接触五条细丝，根部轻微分散后仍经真实介质体积钳制；远处旧连接只淡出显示。64 个物理接触、水平活动范围、竖向断裂距离和总拉力保持原有规则。
- 所有材质共享较薄的默认凸起。不可见的外层不再撑开覆盖；可见普通外层、立体外层仍按各自尺寸避让。透明度、UV、高度蒙版、清洗与强度配置没有改变。

## 质量检查

- 相机脚点每帧清空、实体弱引用；第三人称立即忽略相机数据。实际 F6 API 开关和切换视角验证无旧帧残留。
- 仅使用可选模组的只读状态和尺寸配置，无强制依赖、上游实体位置修改或上游代码复制。采样使用私有模型；延迟几何提交仅捕获不可变向量和列表。
- 五条细丝和分段数有固定上限，延续按角色/材质显示预算及远处降采样。未做多人高负载帧率基准，不能用单场景通过代替性能证明。
- 第一人称证据来自实际提交的身体腿矩阵，独立于脚部采样器；测试只在显式验收参数下启用。
- 新的薄膜厚度检查先失败后通过；默认凸起和外层可见性均有断言。实际客户端覆盖 600 个材质/宽细臂/等级/部位组合、外层网格、资源重载、强度归零与平面回退。

## 回归中发现的问题

1. 独立操作夹具在批量建池后，只等待服务端任务结束，没有等待客户端区块到达。诊断在第 70 tick 看到地板和胶水均为 `void_air`，导致传送后短暂下落。现等待真实胶水柱与落地状态再传送；原有无被动下陷、累计成本和范围断言完整保留。最终初始高度服务端/客户端均为 252.5。
2. 开发中新增就绪条件曾错误要求落地玩家竖向速度为零，而原版落地后仍保留下一 tick 的重力速度。已改为实际 `onGround()` 和位置检查。
3. 一次串联运行中，旧粘鼠板脱困距离断言失败。增加实际距离和状态诊断后，单独粘鼠板及最终完整操作串联均严格通过，未放宽阈值、修改玩法或移除该断言。旧失败未记录具体距离，无法确定该次失败的进一步原因，保留日志供后续追踪。
4. 追加第三张必要的贴肤对照截图后，启动器日志计数仍显示 2，实际有三个保存标记与对应文件。已把计数修为 3；保留原始验收日志，不改写证据。

未发现当前改动中的阻断性代码问题。已知边界：立体皮肤外层仍按部件最大尺寸整体避让，并非逐个皮肤透明像素重新贴面；其他身体变形模组、所有用户皮肤及双真人联机未穷尽验证。
