# 审查与修复计划

1. 验证备份 ZIP、bundle 与 JAR，记录来源提交；读取生产、验证、测试和工具文件清单。
2. 运行现有 Gradle `check`、Python 测试、打包资源和生成数据验证，记录未经修改的基线。
3. 服务端审查覆盖玩法、实体、物品、世界生成、兼容配方与方块实体；主代理审查客户端、网络、方块、流体、配置、注册、数据生成和工具。每项发现记录具体触发、影响及代码证据。
4. 对确认缺陷先建立失败用例，实施最小修复；优先处理物品丢失/复制、存档破坏、权限与生命周期，再处理渲染缓存、性能和边界。
5. 运行受影响回归，并根据变化选择已有隔离服务器、持久化或客户端场景。图片仅用于必要视觉核验。
6. 复核修复差异、保存覆盖清单与审查记录；构建独立的新 dev JAR，记录校验和交付范围。
